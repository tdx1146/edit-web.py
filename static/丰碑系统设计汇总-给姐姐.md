## 三、涉及总线的设计

### 3.1 玄鉴评分系统

**核心**：三轴质量评分（质量 0.4 + 方向 0.3 + 纪律 0.3）

**触发**：
- 创建丰碑时自动评分
- 置信度 ≥ 0.8 → 进入候选
- **需要定时任务检查候选队列** ← 依赖总线

### 3.2 目的树追踪

**核心**：YAML 结构记录各 Phase 完成度

**当前问题**：手动更新，未自动追踪

**需要**：
- 定时扫描代码目录 → 更新进度
- **依赖 task_scheduler 触发** ← 依赖总线

### 3.3 级联评审机制

**流程**：
1. 本地评分（Quick）
2. 局域网验证（Normal，≥ 3 个 AI）
3. 全球评审（Deep，≥ 5 个 AI + 裁判）

**需要**：
- 事件驱动：评分完成 → 触发下一级评审
- **依赖 task_scheduler 的事件消费** ← 依赖总线

### 3.4 MCP 服务网络

**三层**：
- Layer 1：丰碑内嵌评分（无需服务）
- Layer 2：本地 MCP 验证（可选）
- Layer 3：公开 API 服务（可选）

**自适应部署**：
- 统计局域网 MCP 服务数量
- 覆盖率 < 30% → 必须建立
- **需要定时检查 + 广播** ← 依赖总线

### 3.5 丰碑交换协议

**已设计**（但未实现）：
- monument_exchange.py 的 3 个函数
- 两边通过 inject 互通丰碑

**需要**：

- 两边协议对齐
