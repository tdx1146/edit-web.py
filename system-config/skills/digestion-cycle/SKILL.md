# 🔄 消化循环

> 消化 = 从轮感/对话中提取结构、索引断言、保持一致性的自动化流程。
> 不是创建 Skill。Skill 是摸摸确认后才发生的事。

## 输入

- L1 会话上下文（自上次消化以来的新对话轮次）
- L2 每日日志（memory/YYYY-MM-DD.md 最新部分）
- 系统事件（cron/hooks 产生的内部日志）
- 游标追踪（记录上次消化处理到哪，避免重复）

## 流水线（6步）

### Step 1: 采集
扫描新对话 + 新轮感 → 拆分为"原子片段"（按时间间隔/话题切换分割）
- 执行者：主代理
- 故障隔离：挂了下次重试

### Step 2: 断言提取
spawn DeepSeek（结构扫描）+ 混元（隐性假设挖掘）
从原子片段中提取：事实断言、决策记录、重复模式
输出：断言列表（每条带源轮感行号引用 + 置信度初始分 0.7）
- 执行者：子代理（并行）
- 故障隔离：超时/失败 → 跳过断言提取，轮感不丢

### Step 3: 冲突检测
新断言 vs facts.dict.md + MEMORY.md 已有记录比对
冲突标记为 `#conflict` 等待摸摸时人工审
一致则合并更新置信度
- 执行者：规则引擎（不调LLM）
- 故障隔离：纯规则不会挂

### Step 4: 索引写入
新断言追加到 facts.dict.md（带行号引用 + 时间戳 + 置信度）
同步更新 MEMORY.md（保持一致性）
写入 memory/YYYY-MM-DD.md 尾部（每日消化摘要）
- 执行者：主代理
- 故障隔离：文件写失败 → 打 log 下次重试

### Step 5: 摸摸候选检测
扫描本次消化的产物，找出"值得摸摸时给 dandan 看"的项：
- 有冲突需要判断的 `#conflict`
- 重复出现 3 次以上的模式（潜在 Skill 候选）
- 系统异常需要注意的
输出：摸摸候选列表 → memory/摸摸候选.json
- 执行者：主代理
- 故障隔离：跳过不影响

### Step 6: 汇总
写一条结构化摘要到 L2 尾部：
```
消化 (HH:MM): 扫描N条对话 → 提取M条断言 → C条冲突 → K条候选
```
- 执行者：主代理
- 故障隔离：失败了下次补

### Step 7: 断言吸入（利用消化产出）
将本次消化的断言主动注入后续对话的推理上下文，确保消化不是终点而是起点：

1. **记录本轮断言清单**：从 facts.dict.md 尾部提取最新添加的断言（带编号+置信度）
2. **场景匹配**：按对话上下文匹配合适的断言——编辑器问题→L1-L6，架构决策→S1-S6，方法论→M1-M5
3. **轮感追加引用标记**：在 memory/YYYY-MM-DD.md 轮感尾部标注「引用断言：L1, M1, ...」
4. **监控反馈**：断言吸入后编辑器的「📖 读取」计数器会自增，可验证实际使用率
- 执行者：主代理（强制执行，不可跳过）
- 故障隔离：跳过（但监控栏会显示 0 次，dandan 能看到）

| 输出 | 位置 | 格式 |
|------|------|------|
| 断言索引 | facts.dict.md | 行号引用 + 置信度 |
| 长期记忆同步 | MEMORY.md | 结构化 Markdown |
| 每日摘要 | memory/YYYY-MM-DD.md 尾部 | 消化成果块 |
| 摸摸候选 | memory/摸摸候选.json | 待 dandan 审阅的候选列表 |

## 触发

- 定时：每 6h（cron）
- 事件：压缩前（pre-compact hook）
- 手动：dandan 随时触发

## 与摸摸协议的桥接

dandan 按摸摸按钮时：
- 摸摸协议原有 4 步不变（认可 → 打包 → 描述 → 提问）
- 在"描述当下"中自动附带消化摘要（最新断言、冲突、模式）
- 如果有 `#conflict` 或 Skill 候选，在"问主人问题"时提出
- dandan 说"存成 Skill" → 写入 `~/.pi/agent/skills/`
